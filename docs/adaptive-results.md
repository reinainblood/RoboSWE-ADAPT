# Reading adaptive results

`python -m roboswe.adaptive_results jobs` prints a read-only JSON snapshot of the public five-trial series found in that directory. It never contacts a provider or changes a job. The snapshot includes paths and SHA-256 hashes for its job, report, and verification evidence. A recorded running status is not a process-liveness check.

Each series always has five slots. An observed success becomes an official success only when independent code replay reproduces it with valid infrastructure and valid starting preconditions. Failed task outcomes likewise require replay. Missing replay, a provider refusal, infrastructure failure, and an unstarted trial remain separate from an official task failure. Deadline and step-budget censoring are recorded alongside a verified failure when replay supports that outcome. The exporter rejects duplicate attempt numbers rather than choosing a convenient receipt.

The success curve contains true, false, or null for each trial. The verified-success count divided by five is reported together with completion coverage and bounds spanning all unresolved outcomes. These are missing-outcome bounds, not statistical confidence intervals. A final five-trial success fraction and terminal success streak appear only for complete series. A streak of four after an initial failure describes recovery; a streak of five preserves the distinction for immediate reliable success. Neither is described as a causal effect of retained context.

Adjacent successful trials expose changes in control steps and active seconds. Failed trials are not treated as successful cheap solutions. The exporter assigns no composite efficiency or exploration score. A candidate future efficiency measure should require at least three consecutive successful trials, evaluate the full sequence rather than its best pair, and declare a tolerance for noise before comparing models. A single large improvement followed by a plateau or regression should not automatically receive sustained-improvement credit. Recovery from a dropped object is useful evidence for a separately annotated recovery measure, but raw error counts alone should not penalize exploration.

Timing fields distinguish active episode time, episode wall time, passive waiting, model roundtrip, operation roundtrip, and observation roundtrip where the original receipts support them. Provider model compute, transport alone, and authored code alone are null because the present event stream does not cleanly separate those quantities. Roundtrip totals include only recorded completed or errored calls; a currently outstanding call is not assigned an invented duration. These measures exclude setup and replay.

This snapshot covers discovered series only. A full release leaderboard must additionally join the frozen selection manifest so unlaunched tasks remain visible in its denominator, and must group comparable provider, context, and execution configurations. Dependent retained trials do not justify independent-trial binomial confidence intervals. Task-level uncertainty requires a defined task aggregation and sampling procedure. Matched fresh-context controls are needed to support a causal in-context learning claim.
